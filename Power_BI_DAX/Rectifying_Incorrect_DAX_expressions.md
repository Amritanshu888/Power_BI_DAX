# 5. First Attempt: Using the SUM Function

The instructor initially tries to solve the requirement using the `SUM()` function.

---

# 6. Error Generated by SUM

When the instructor executes the expression, Power BI generates an error.

The important error message is:

> **The SUM function only accepts a column reference as an argument.**

### Why does this happen?

The `SUM()` function is designed to aggregate the values of **one column**.

Its general syntax is:

```DAX
SUM(Table[Column])
```

It expects a **column reference** as its argument.

For example:

```DAX
SUM(Sales[SalesAmount])
```

is valid.

But something like:

```DAX
SUM(Sales[Quantity] * Sales[Price])
```

is not valid because:

```DAX
Sales[Quantity] * Sales[Price]
```

is an **expression**, not a direct column reference.

---

# 7. Understanding the Problem

The requirement is slightly different from simply adding the values of a column.

We don't want:

```text
SUM(Column A)
```

or:

```text
SUM(Column B)
```

Instead, we want:

```text
(Column A × Column B) for every row
```

and then:

```text
SUM(all those products)
```

Therefore, we need a DAX function that can **iterate through rows and evaluate an expression for each row**.

This is where `SUMX()` becomes useful.

---

# 10. Understanding SUMX

`SUMX()` is an **iterator function**.

Its basic syntax is:

```DAX
SUMX(<table>, <expression>)
```

It has two major arguments:

### First argument — Table

The table over which DAX should iterate.

Example:

```DAX
'Screen Time'
```

### Second argument — Expression

The calculation that should be performed for each row.

Example:

```DAX
'Screen Time'[Average Daily Screen Time]
*
'Screen Time'[Educational to Recreational Ratio]
```

Therefore, conceptually:

```DAX
SUMX(
    'Screen Time',
    'Screen Time'[Average Daily Screen Time]
        *
    'Screen Time'[Educational to Recreational Ratio]
)
```

---

# 11. How SUMX Solves the Problem

Suppose the data looks like this:

| Row | Avg. Daily Screen Time | Educational : Recreational Ratio | Product |
| --: | ---------------------: | -------------------------------: | ------: |
|   1 |                      4 |                              0.5 |       2 |
|   2 |                      6 |                             0.25 |     1.5 |
|   3 |                      8 |                              0.5 |       4 |

`SUMX()` effectively performs:

```text
Row 1 → 4 × 0.5 = 2
Row 2 → 6 × 0.25 = 1.5
Row 3 → 8 × 0.5 = 4
```

Then:

```text
2 + 1.5 + 4 = 7.5
```

So the overall calculation is:

$$
\text{SUMX} = \sum(\text{Column 1} \times \text{Column 2})
$$

This is exactly what the requirement asks for.

# 13. Key Difference: SUM vs SUMX

This is one of the most important concepts demonstrated in this lecture.

| `SUM()`                                   | `SUMX()`                              |
| ----------------------------------------- | ------------------------------------- |
| Adds values from a single column          | Iterates through a table              |
| Accepts a column reference                | Accepts a table and an expression     |
| Does not evaluate a row-by-row expression | Evaluates an expression for every row |
| Simple aggregation                        | Iterator/row-by-row calculation       |
| `SUM(Table[Column])`                      | `SUMX(Table, Expression)`             |

### Example

If you simply want:

```text
Sum of Sales Amount
```

use:

```DAX
SUM(Sales[Sales Amount])
```

But if you want:

```text
Quantity × Price for every row
then sum the results
```

use:

```DAX
SUMX(
    Sales,
    Sales[Quantity] * Sales[Price]
)
```

# 15. AI Explanation of SUM vs SUMX

The generated explanation essentially says:

### SUM

`SUM()` adds up values from a **single column**.

Example:

```DAX
Total Sales =
SUM(Sales[Sales Amount])
```

It simply takes the values from the specified column and adds them.

---

### SUMX

`SUMX()` is an **iterator**.

It:

1. Iterates through the rows of a table.
2. Calculates an expression for each row.
3. Adds all the calculated results.

Example:

```DAX
Total Revenue =
SUMX(
    Sales,
    Sales[Quantity] * Sales[Price]
)
```

Here, Power BI effectively calculates:

```text
Row 1 → Quantity × Price
Row 2 → Quantity × Price
Row 3 → Quantity × Price
...
```

and then sums those results.

---

# 16. Interview Perspective

The `SUM` vs `SUMX` distinction is an important DAX interview topic.

A concise interview answer would be:

> **SUM aggregates the values of a column, whereas SUMX iterates over a table, evaluates an expression row by row, and then sums the resulting values.**

### Example

**SUM:**

```DAX
SUM(Sales[Amount])
```

**SUMX:**

```DAX
SUMX(
    Sales,
    Sales[Quantity] * Sales[Price]
)
```

The second example requires row-by-row calculation, which is why `SUMX()` is appropriate.

# 21. Don't Blindly Trust AI-Generated DAX

Another important lesson is that AI-generated expressions should not simply be copied without understanding them.

AI can sometimes:

* Misinterpret your requirement.
* Produce an inappropriate function.
* Use an incorrect table/column reference.
* Provide an unnecessarily complicated solution.
* Produce DAX that technically works but isn't the best approach.

Therefore:

> **Always understand and validate the DAX generated by AI.**

Your knowledge of DAX fundamentals allows you to determine whether the AI-generated solution is actually appropriate.

# 23. Important Concepts to Remember

### `SUM()`

Use when you want to add values directly from a column.

```DAX
SUM(Table[Column])
```

### `SUMX()`

Use when you need to calculate something for each row and then add the results.

```DAX
SUMX(
    Table,
    Expression
)
```

### Iterator

Functions such as `SUMX()` are called **iterator functions** because they iterate over the rows of a table and evaluate an expression for each row.
